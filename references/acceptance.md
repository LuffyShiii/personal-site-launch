# 验收与交接

对每项留下证据或明确未完成原因；“测试通过 N 项”不能代替下面的结果。项目未选择的栏目或语言标不适用，用户明确暂缓的目标保留暂缓原因。不要悄悄降低必备自动更新能力。

## 页面与首次上线

- 有用户确认的视觉方向和实际桌面/手机截图，设计图不能冒充真实页面。
- 栏目、精选/完整列表、分页、站内阅读/外跳、语言切换符合确认方案；少量素材按实数展示。
- 用访客身份检查作品和联系入口，识别私有仓库、登录限制、错误平台按钮。外部限流或反爬记为未确认，不凭一次网络失败断定链接失效。
- 检查窄屏、长标题/简介、不同图片比例、键盘焦点和导航。图片显示缩小不等于传输体积变小，按本项目性能目标实际核对。
- 标题、描述、分享信息及规范链接等按项目需要配置并核对。不要把未经需求确认的分析工具、付费域名或复杂 SEO 功能加入交付。
- 首次公开上线有明确授权，正式网址可访问，生产版本与预期一致；普通访客不能读取草稿或私密原始资料。

## 内容与独立自动更新

- 用户可复制并填写普通文本模板；不需要学习内部语法、ID 或 Git。
- 新增、修改、换序、取消精选、草稿、明确下架均验证；中英/项目实际语言的字段按需求检查。
- 中文与空格路径，至少覆盖新增、再次修改、Git 历史读取及误删保护。
- 缺封面/链接、未知状态、重复或冲突资料能给具体问题，旧有效页面保留；错误输入不能被静默过滤后造成内容消失。
- 文件复制未完成、连续保存、构建期间修改、重复触发只产生正确批次，持久队列可重启续接。
- 真正断网并超出短重试窗口，再恢复网络：保持输入不变，不手动触发，程序自动完成更新并通知。网络抖动不会无限重置重试预算。
- 权限失效、构建失败和冲突停止且提示正确原因，不假装都是网络错误。
- 成功和失败通知都实际验证；通知权限关闭时有可见反馈，不能只有程序“调用成功”的日志就当成用户必然看见。
- 正常停止、重启和意外退出状态准确，通知及日志可查。关闭聊天窗口后服务仍运行；断电/睡眠等条件如实说明。
- 既能看到服务是否运行，也能看到最近网页发布状态；服务停止不会被最近一次 published 掩盖。

## 版本恢复的真实演练

优先使用实际托管平台上的隔离/预览分支。记录生产基线，执行：

1. 发布正常 A，保存关键页面和资源的内容/校验值、部署版本。
2. 发布有明确变化的 B，验证浏览器或 HTTP 实际提供 B。
3. 在隔离环境制造确定的构建失败，确认平台判失败，仍提供上一成功版本 B。
4. 用新提交/平台已授权的恢复机制恢复 A；确认内容、必要资源与预期 A 一致，记录新版本和操作步骤。
5. 确认生产在演练期间未变，说明恢复的是预览还是生产，哪些操作仅演练、哪些真实改动。

记录恢复方法的适用范围：源码恢复、重新发布旧内容和托管控制台回滚不是同一操作，不要验证一个就宣称所有方式通过。已有未提交资料先保存，选择恢复范围，不无差别硬重置或强制推送。隔离测试文件与实际用户作品分开，临时测试资产可清理，用户自己的“test”文件不能擅自删除。

## 用户亲自更新与收尾

用户亲自填写/修改一条真实素材并放入本地文件夹。Agent 可以解释模板、观察和排错，但不能代替完成后声称“用户已学会”。确认四个结果：资料被接收、网站真实变化、用户收到反馈、用户知道如何停止及寻求恢复。

交付：实际网站地址、素材入口和样例、简明操作说明、停止/重试入口、恢复方法、当前范围与限制、可续接的项目记录。没有完成这一步时标记“等待用户自主更新验收”，不要为了结束任务写成全项完成。

## Skill 包本身的验证边界

SKILL.md 格式校验和转换器单元测试只能证明文件包与辅助工具的部分行为，不能证明在 Codex/Kimi、所有操作系统完成了整套建站。后续真实使用应记录 Agent 名称/版本、系统、能力、托管、实际创建的页面、同步/通知/恢复证据；再更新兼容性声明。未获授权不为测试创建付费资源或动生产站。
