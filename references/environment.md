# 环境与跨 Agent 适配

## 能力先于品牌

SKILL.md 和相对路径资源是通用核心。不要在核心流程绑定某个 Agent 的工具名、账号、电脑路径、网站代码或托管平台。agents/openai.yaml 只是 Codex 的可选界面元数据；其他 Agent 不需要执行它。

开始时确认当前环境能否：

| 能力 | 如何判断与处理缺口 |
| --- | --- |
| 读取和修改本机文件 | 实测选定工作目录读写；云端执行目录不能冒充用户电脑的本地文件夹 |
| 执行构建/校验 | 探测已有运行时并使用项目匹配版本，不为方便改变全局设置 |
| 展示图片与实际网页 | 用可用的图片/浏览器工具；截图和设计图明确标注，不能伪造截图 |
| 连接托管与源码服务 | 优先已有合适的 API/CLI/连接器；不足时使用可用浏览器，按工具规则处理登录 |
| 常驻运行与通知 | 电脑上的独立程序和系统服务，不能用 Agent 当前 shell 会话代替长期服务 |
| 记录和恢复 | 用户可访问的持久 Markdown、状态、事件日志和版本记录 |

能力不足时仍可完成独立的需求/设计工作。必须把本地同步交付标记为阻塞，明确需要哪种本地执行环境、安装或权限；不要把“生成了脚本”“提供了下载”写成“已经安装并运行”。

## Agent 接入

本包采用 Markdown + YAML 前置信息的 SKILL.md，引用资源都在同一目录。共享时分发整个目录，不只复制 SKILL.md。

- Codex：按当前宿主的技能目录规范安装整包。此次制作环境提供 ~/.codex/skills 作为技能根目录；其他版本应核对其实际技能目录，不把此路径视为跨版本保证。可使用 `$personal-site-launch` 明确调用，或在未自动发现时要求 Agent 读取整包入口。
- Kimi Code：根据当前官方文档，未设置 KIMI_CODE_HOME 时，可将完整目录放在 ~/.kimi-code/skills/personal-site-launch；若设置了该变量，则使用其 skills 子目录。新会话中可调用 `/skill:personal-site-launch`。这是官方文档适配路径，尚不等于在用户实际版本完成安装验证。
- 其他支持 SKILL.md 的 Agent：采用其文档规定的发现位置，保留相对资源路径；没有技能机制时，可让具有必要能力的 Agent 读取 SKILL.md 作为工作流程。
- “Kimi”或其他品牌的不同产品不能视为同一执行环境。云端聊天支持上传 skill，也不自动意味着能访问用户本机文件、安装系统服务或接收桌面通知。

安装说明应在目标环境重新确认。Kimi 官方参考（核对日期 2026-11-25）：
[Agent Skills](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/skills.html) · [桌面设置与扩展](https://www.kimi.com/code/docs/en/kimi-code-desktop/settings-and-extensions.html)。

## 电脑与托管适配

- macOS：可评估用户级登录启动任务和本地通知程序；验证桌面权限及退出聊天后的运行状态。
- Windows：评估用户级计划任务/适当的常驻程序及通知；测试带空格与中文路径、登录/注销及睡眠恢复。
- Linux：评估用户级服务与桌面通知；没有图形会话时需要另一个用户确认的通知方式。

这些是实现方向，不是预先验证的安装配方。不要把 macOS 启动项复制成 Windows 方案，不给未经实测的服务命令标“已通过”。安装、卸载和通知应最小化权限并留有操作入口。

框架、源码服务和托管平台根据现有能力、用户预算及静态展示需求选择。不默认购买域名；服务提供的地址若满足用户要求即可交付。记录部署目标、生产分支、构建/输出位置和环境变量。公开访客只能接触公开页面，草稿只保留本地或用户同意的私有源码库。

## 验证边界

本包包含：通用流程、模板、参考要求和只读普通文本转换器。它不会自行创建网站、安装常驻服务或发布内容；执行此 skill 的 Agent 必须在具体项目中完成这些工作。

已在制作环境测试的是转换器、文件包结构和资源链接。Codex 的创作/安装环境、Kimi 文档适配、未来真实 Agent 端到端测试必须分别记录。未实际运行 Kimi Code 或 Windows/Linux 发布与通知流程时，不得称为已实测兼容。
