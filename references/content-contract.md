# 普通文本素材约定

## 用户编辑的文件

每条作品一个文件夹，至少有说明.txt 和封面。按用户习惯生成栏目目录名，如“视频”“文章”“项目”，不要求英文目录和技术编号。文件夹、封面支持中文和空格；目录移动、改名不能被当作无声下架。

将 assets/作品说明模板.txt 复制成真实样例，并告诉用户：

- 填标题、简介、作品链接；封面放同一文件夹。
- 一张封面可自动识别，多张时明确填写封面文件名。
- 发布状态填写“发布”且资料完整时，按已确认规则自动公开；“草稿”不公开；已公开作品用“下架”撤下，不靠删除文件。
- 日期如不确定可不填；系统收录时间不得冒充真实创作/发布日期。
- 精选数量按项目约定，不强制所有网站都是五条。空白或“不精选”只影响精选展示，不等同于下架。

现成转换器以 UTF-8/UTF-8 BOM、带 BOM 的 UTF-16 纯文本为入口，不把 Word 二进制文件误当文本；其他资料格式应明确转换路径。项目至少提供一份用户实际打开、修改、保存成功的样例。

## 转换器与边界

执行示例（由 Agent/程序调用，用户不需要输入命令）：

```sh
python3 scripts/parse_content.py '/素材/示例作品/说明.txt' --languages zh
python3 scripts/parse_content.py '/素材/Example/说明.txt' --languages zh,en --featured-limit 5
```

输出 JSON 为内部规范记录，状态为 ready、draft、withdrawn、needs_input。退出码 0 表示解析完成；2 表示需用户补充/纠正；其他非零为程序错误。该脚本只读输入，不联网、不提交、不修改素材，不等于完成发布。示例诊断文本目前为中文；非中文项目需在实现时提供对应的通知文本映射，不依赖常驻模型临时翻译。

英文项目可用 assets/content-template-en.txt；首个语言决定无语言前缀字段的归属。内置语言字段覆盖中文和英文；增加其他语言时应扩展字段映射并测试，不能仅传入任意语言代码就声称支持。

标题与简介允许换行，支持中文/英文冒号及常见字段别名；中英发布状态大小写不敏感。重复字段必须报错，不能只保留最后一项。程序不猜封面、不猜未知字段，也不把字段内容当作 shell 命令或代码执行。

若网站需要双语，说明模板中增加英文标题/简介。缺少翻译时进入待完善，交由 Agent 协助补齐并让用户审阅；不在后台循环里调用模型擅自补写后发布。该转换器不处理个人资料模板；按项目需求另做个人资料的整理与校验。

## 身份与状态

用户不维护 ID。由程序给每条作品分配稳定内部标识，持久保存，例如随作品移动的隐藏元数据文件和队列索引。更换标题、封面、精选位置不会变成新作品；复制文件夹导致 ID 冲突时提醒用户，不覆盖已有作品。改名/搬移无法可靠判断时暂挂并说明，不自动删除线上内容。

不完整的“发布”记录返回 needs_input。新记录不上线；已存在的线上条目保留最后有效版本。默认按完整批次校验，失败则整批保持上一正常版本；不能通过过滤错误条目生成一个缺内容的新网站。

“草稿”可以不完整；为降低初次填写负担，缺失内容仍以提醒列表告知。“下架”必须关联已知作品，未识别的身份先要求确认，不把空文件夹或暂时不可读视为下架请求。

校验分层：文本与字段 → 跨条目 ID/精选冲突 → 图片是否真正可解码及尺寸 → 站点构建 → 访客链接/部署。转换器只覆盖第一层和本地封面定位，不能用其成功替代全站验收。

## 防止格式误判

读取 Git 路径使用 -z/NUL 分隔等原始路径接口，不解析带引号/转义的展示文本。实际授权目录用规范化路径和边界检查，不用脆弱的字符串前缀替代路径判断。素材软链接、目录逃逸和构建期间变化应明确阻断。中文与空格是正常输入，必须纳入真实新增/修改/下架回归。

素材读取稳定不代表全部已复制完成。至少校验所需文件完整并能读取，构建使用一致快照；过程中变更时取消这一批并处理新快照。旧成功输出原子替换，不能先清空线上目录再开始失败概率不明的工作。
