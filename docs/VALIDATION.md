# personal-site-launch 首版验证与交付

日期：2026-11-25。用途：非技术用户个人展示网站，从需求、图片确认到真实上线、本地文件夹自动更新及用户自主维护验收。

## 已交付

- 通用 SKILL.md：以能力选择工具，未绑定具体 Agent、操作系统、框架、账号或托管商。
- 4 份按需参考：环境适配、素材约定、自动更新、验收与恢复。
- 5 份模板：中文作品、英文作品、个人资料、项目记录、操作说明。
- 只读普通文本转换器与行为测试：由 Agent/同步程序调用，内部 JSON 不暴露为用户的编辑要求。
- Codex 可选界面元数据与完整 ZIP 分享包。

- skill-creator quick_validate：通过。
- 普通文本转换器：21 项行为测试通过，包含中文/空格、多行、中英文、缺失信息、多封面、重复字段、路径越界、状态、日期、UTF-8 BOM/UTF-16/CRLF、只读和 CLI 退出码。

- 本次没有更改现有网站的代码、素材或后台自动发布服务。

## 工作流静态审阅（不是独立 Agent 实测）

| 场景 | 指令中要求的行为 |
| --- | --- |
| 用户只想先讨论 | 不提前创建或部署 |
| 不同 Agent 或云端无本地文件能力 | 探测能力，给补齐路径，不能冒充已安装本地服务 |
| 尚未确认设计 | 展示图片，确认后完整开发 |
| 用户放入不完整素材 | 待完善、具体提示、保留旧页面 |
| 无新编辑但网络恢复 | 持久队列自动继续，不依赖手动 retry，仍遵守预算 |
| 同一故障不断触发 | 合并通知、有限重试、保留停止与恢复入口 |
| 推送成功但网站未更新 | 不报发布成功 |
| Agent 完成测试而用户未亲自更新 | 用户自主验收仍待完成 |
| 用户说今天结束或暂缓某项 | 记录进度，不擅自扩展工作或停止授权服务 |

## 不能声称已完成的验证

没有在 Kimi Code、Windows/Linux 或另一个用户的新网站上执行完整建站、后台安装、通知与联网恢复流程。Kimi 适配依据当前官方技能文档；格式兼容不是全链路实测成功。本包是执行建站任务的 skill 和辅助工具，不是已为所有操作系统安装好的通用发布器；使用它的 Agent 必须在每个具体项目实施必备自动更新并验收。

后续应在真实目标环境记录 Agent/版本、系统、部署平台、实际用户操作和结果，再扩大已验证范围。

## 用户使用

给其他人分享整个 personal-site-launch.zip。按目标 Agent 的技能加载方式安装完整文件夹；没有自动加载能力时，要求具有本地执行能力的 Agent 读取目录中的 SKILL.md 及按需参考。不要仅分享入口文件而遗漏相对引用的模板和脚本。

建议起始请求：“请使用 personal-site-launch 帮我建立个人展示网站。我没有技术背景，请先聊清楚需求，用图片让我确认设计，然后完成上线、文件夹自动更新和实际验收。”

本仓库根目录即技能目录。正式入口：[SKILL.md](../SKILL.md)。兼容性及接入方式见 [环境说明](../references/environment.md)。
